## Local Development Setup

### Prerequisites

- **Node.js** 18+ (for frontend)
- **Python** 3.11+ (for backend)
- **Docker & Docker Compose** (recommended for database)
- **Git**

### Step 1: Clone & Navigate

```bash
git clone https://github.com/will92-tech/auto-parts.git
cd auto-parts
```

### Step 2: Setup Backend

#### Option A: Docker (Recommended)

```bash
cd backend
docker compose up --build
```

This will:
- Start PostgreSQL 15 on port 5432
- Start FastAPI on port 8000
- Auto-create database tables
- Open http://localhost:8000/docs for API documentation

#### Option B: Local Python

```bash
cd backend
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Edit `.env` with your local database URL:
```bash
DATABASE_URL=postgresql://user:password@localhost:5432/autoparts
SECRET_KEY=dev-secret-key-change-in-production
```

Run the server:
```bash
uvicorn main:app --reload
```

Verify it's running:
```bash
curl http://localhost:8000/health
# Response: {"status":"healthy"}
```

### Step 3: Setup Frontend

```bash
npm install
cp .env.local.example .env.local
```

Edit `.env.local`:
```bash
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Start dev server:
```bash
npm run dev
```

Open http://localhost:3000 in your browser.

### Step 4: Verify Everything Works

**Frontend:**
- Homepage loads at http://localhost:3000
- Shop page loads at http://localhost:3000/shop
- Can browse products (loaded from backend)

**Backend:**
- Health check: `curl http://localhost:8000/health`
- API docs: http://localhost:8000/docs
- Try test endpoint: `curl http://localhost:8000/api/products`

### Deployment Options

#### Option 1: Railway (Recommended - Easiest)

Railway provides one-click deployment for both frontend and backend.

**Step 1: Create Railway Account**
- Go to https://railway.app
- Sign in with GitHub
- Create new project

**Step 2: Deploy Backend**

```bash
# Install Railway CLI
npm install -g @railway/cli

# Login
railway login

# Link project
railway link

# Deploy backend
cd backend
railway up
```

Railway will:
- Auto-detect FastAPI app
- Provision PostgreSQL database
- Set environment variables
- Deploy on `railway.app` domain

**Step 3: Configure Backend Environment**

In Railway dashboard:
- Go to Backend service → Variables
- Set:
  ```
  DATABASE_URL=<auto-generated>
  SECRET_KEY=<generate-strong-key>
  ALGORITHM=HS256
  ACCESS_TOKEN_EXPIRE_MINUTES=30
  CORS_ORIGINS=["https://your-frontend-domain.railway.app"]
  ```

**Step 4: Deploy Frontend**

```bash
cd ..
railway up
```

In Railway dashboard:
- Go to Frontend service → Variables
- Set:
  ```
  NEXT_PUBLIC_API_URL=https://your-backend-service.railway.app
  ```

**Step 5: Verify Production**

- Frontend: https://your-project.railway.app
- Backend: https://your-backend.railway.app/docs
- Check logs in Railway dashboard

---

#### Option 2: Render.com

**Step 1: Connect GitHub**
- Go to https://render.com
- Sign in with GitHub
- Connect your repository

**Step 2: Deploy Backend**

Create `render.yaml` in repository root:

```yaml
services:
  - type: web
    name: autoparts-api
    env: python
    buildCommand: cd backend && pip install -r requirements.txt
    startCommand: cd backend && uvicorn main:app --host 0.0.0.0 --port $PORT
    envVars:
      - key: DATABASE_URL
        fromDatabase:
          name: autoparts-db
          property: connectionString
      - key: SECRET_KEY
        generateValue: true
      - key: ALGORITHM
        value: HS256

  - type: web
    name: autoparts-web
    env: node
    buildCommand: npm install && npm run build
    startCommand: npm start
    envVars:
      - key: NEXT_PUBLIC_API_URL
        value: https://autoparts-api.onrender.com

  - type: pserv
    name: autoparts-db
    ipAllowList: []
    plan: free
```

Then deploy via Render dashboard.

#### Option 3: AWS (Scalable)

**Backend: ECS + RDS**
```bash
# 1. Create ECR repository
aws ecr create-repository --repository-name autoparts-api

# 2. Build & push Docker image
cd backend
docker build -t autoparts-api .
docker tag autoparts-api:latest <account-id>.dkr.ecr.<region>.amazonaws.com/autoparts-api:latest
docker push <account-id>.dkr.ecr.<region>.amazonaws.com/autoparts-api:latest

# 3. Create RDS PostgreSQL database
aws rds create-db-instance \
  --db-instance-identifier autoparts-db \
  --db-instance-class db.t3.micro \
  --engine postgres \
  --master-username admin \
  --master-user-password <strong-password> \
  --allocated-storage 20 \
  --publicly-accessible

# 4. Create ECS task definition & service
# (Use AWS Console or CloudFormation)

# 5. Set environment variables in ECS task definition
# DATABASE_URL, SECRET_KEY, etc.
```

**Frontend: CloudFront + S3**
```bash
# 1. Build Next.js app
npm run build

# 2. Deploy to S3
aws s3 sync .next/static s3://autoparts-frontend/

# 3. Create CloudFront distribution pointing to S3
# (Use AWS Console or CloudFormation)
```

### Environment Configuration for Production

Create `.env` file on production server (never commit):

```bash
# ═══════════════════════════════════════════════════════════
# DATABASE
# ═══════════════════════════════════════════════════════════
DATABASE_URL=postgresql://admin:STRONG_PASSWORD@autoparts-db.xxxxx.rds.amazonaws.com:5432/autoparts

# ═══════════════════════════════════════════════════════════
# SECURITY (Generate strong keys!)
# ═══════════════════════════════════════════════════════════
SECRET_KEY=your-production-secret-key-min-32-chars-strong-random
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30

# ═══════════════════════════════════════════════════════════
# API SETTINGS
# ═══════════════════════════════════════════════════════════
API_TITLE=AutoPartsPro API
API_VERSION=1.0.0
API_DESCRIPTION=Kenya's automotive parts e-commerce platform

# ═══════════════════════════════════════════════════════════
# CORS (Set to your frontend domain)
# ═══════════════════════════════════════════════════════════
CORS_ORIGINS=["https://autopartspro.co.ke", "https://www.autopartspro.co.ke"]

# ═══════════════════════════════════════════════════════════
# M-PESA (Safaricom Daraja)
# ═══════════════════════════════════════════════════════════
MPESA_CONSUMER_KEY=your-daraja-consumer-key
MPESA_CONSUMER_SECRET=your-daraja-consumer-secret
MPESA_PASSKEY=your-mpesa-passkey
MPESA_BUSINESS_SHORTCODE=your-shortcode
MPESA_ENVIRONMENT=production
```

**Generate Strong Secret Key:**
```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

## Monitoring & Troubleshooting

### Check Backend Health

```bash
# Health check endpoint
curl https://your-backend-domain.com/health

# API documentation
https://your-backend-domain.com/docs

# Check logs (varies by platform)
railway logs     # Railway
render logs      # Render
aws logs tail    # AWS
```

### Common Issues

**Issue: "Could not validate credentials"**
- Problem: JWT token expired or SECRET_KEY mismatch
- Solution: Ensure SECRET_KEY is same across all backend instances

**Issue: "Connection refused to database"**
- Problem: DATABASE_URL incorrect or database down
- Solution: Check DATABASE_URL format and database service status

**Issue: CORS errors in frontend**
- Problem: Frontend domain not in CORS_ORIGINS
- Solution: Add frontend domain to backend CORS_ORIGINS env var

**Issue: Products not loading**
- Problem: API URL incorrect in frontend
- Solution: Verify NEXT_PUBLIC_API_URL matches backend URL

### Performance Optimization

**Backend:**
```python
# Use connection pooling
engine = create_engine(
    DATABASE_URL,
    poolclass=QueuePool,
    pool_size=10,
    max_overflow=20,

CREATE INDEX idx_user_email ON user(email);
```
